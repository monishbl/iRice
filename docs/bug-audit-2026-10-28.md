## High

### R01 — Login/TTY sessions omit the ordinary idle and sleep lock service

**Trigger and impact:** The login-screen session starts `sandbox/hypr/tty.lua`. Unlike the installed desktop configuration, this startup path never starts `hypridle`. The shell's own idle lock runs only when StandBy is enabled **and the battery is charging**. On battery, or with StandBy disabled, the session can remain unlocked indefinitely while idle. Choosing Sleep also directly invokes suspend, without acquiring a lock first; without an independently running lock service, resuming can expose the desktop.

**Evidence:** Code inspection. This specifically concerns the login/TTY path; the installed path that starts `hypridle` has separate protection. Sources: [TTY startup](../sandbox/hypr/tty.lua#L49), [login entry point](../sandbox/irice-session.sh#L44), [conditional shell idle lock](../shell/modules/lock/Lock.qml#L163), [power actions](../shell/services/System.qml#L109).

### R02 — The lock animation starts before the compositor is actually locked

**Trigger and impact:** With the default zoom transition and wallpaper running, a lock request sets the visual veil and waits 400 ms before setting `held`, which controls `WlSessionLock.locked`. During that interval the overlay has an empty input region and does not acquire the session lock. Input can still reach the application underneath; quickly typing a password can put its first characters into that application. A shell failure in the interval also occurs before lock acquisition.

**Evidence:** Code inspection; no password or live lock test performed. Sources: [transition](../shell/modules/lock/Lock.qml#L49), [400 ms timer](../shell/modules/lock/Lock.qml#L92), [input-transparent veil](../shell/modules/lock/Lock.qml#L145), [actual lock binding](../shell/modules/lock/Lock.qml#L256).

### R03 — LocalSend receives files without transport encryption

**Trigger and impact:** The helper advertises HTTP and starts an ordinary HTTP server. Transfers into iRice therefore expose file contents and transfer tokens to an observer on the network path. Outgoing HTTPS also disables certificate verification and does not establish a trusted peer identity. The implementation offers no encryption setting or indication that receiving is unencrypted.

**Evidence:** Code inspection. HTTP is allowed by the protocol, so this is a security limitation of the implementation rather than a claim that HTTP is protocol-invalid. Sources: [advertised protocol](../shell/assets/scripts/localsend.py#L56), [HTTPS verification disabled](../shell/assets/scripts/localsend.py#L81), [HTTP server](../shell/assets/scripts/localsend.py#L264). The official [LocalSend protocol](https://github.com/localsend/protocol#2-fingerprint) distinguishes encrypted HTTPS from unencrypted HTTP.

### R04 — Watcher cleanup can terminate a process group that no longer belongs to iRice

**Trigger and impact:** After a watcher record survives a crash, its process-group ID may eventually be reused. The reaper accepts members whose start time is **greater than or equal to** the old group's start time. A completely unrelated later group passes that test. Cleanup then sends TERM and potentially KILL to the whole group, risking application termination and unsaved work.

**Evidence:** Reproduced safely with `--dry-run`: an ancient synthetic record selected a newly created, unrelated `sleep` process group. No reaper signals were sent. Source: [identity test and group kill](../shell/assets/scripts/reap-watchers.sh#L32).

### R05 — Accepted file size does not limit the bytes a sender can write

**Trigger and impact:** The receive prompt displays sizes from preparation metadata, but the upload handler trusts a new HTTP `Content-Length` without comparing it with the accepted size. A sender accepted for a tiny file can send a much larger one, potentially filling the Downloads filesystem. Request-body reads and request threads also lack application-level size/time/concurrency limits, widening the resource-exhaustion risk while the helper is reachable.

**Evidence:** Reproduced the consent-size mismatch: accepted metadata said one byte; ten bytes were written and reported complete. Disk exhaustion itself was not attempted. Sources: [prompt metadata](../shell/assets/scripts/localsend.py#L215), [upload length](../shell/assets/scripts/localsend.py#L237), [unbounded body read](../shell/assets/scripts/localsend.py#L175).

## Medium

### R06 — An incomplete incoming transfer is reported as successful

An early EOF breaks the upload loop, but the code never checks that all declared bytes arrived. It retains the partial file, responds with success, and emits `finished`. Reproduced: five bytes of a declared 100-byte upload produced a completed transfer. Source: [upload loop and completion](../shell/assets/scripts/localsend.py#L240).

### R07 — Cancelling a receiving transfer does not cancel its active writer

Cancellation removes the session from the global dictionary. An upload already in progress retains its local reference and never checks a cancellation flag, so it continues writing and can emit success after the cancellation. Reproduced by cancelling between chunks: the complete file was still written and a `finished` event followed `failed`. Sources: [active upload](../shell/assets/scripts/localsend.py#L230), [cancel command](../shell/assets/scripts/localsend.py#L360).

### R08 — Concurrent incoming uploads can overwrite one another

The filename helper checks whether a path exists, then the upload opens it separately with `wb`. Two upload threads choosing the same basename can both select the same free path and truncate/write the same destination. Reproduced with two synchronized upload threads: both recorded the same path and only one payload remained. Sources: [non-atomic name selection](../shell/assets/scripts/localsend.py#L152), [file creation](../shell/assets/scripts/localsend.py#L236).

### R09 — One malformed discovery message can stop LocalSend discovery until restart

The exception handler covers JSON decoding, but not validating or consuming the decoded object. Valid JSON such as `[]`, or a device object with a nonnumeric port, raises outside that handler and terminates the discovery thread. The helper itself remains alive, hiding the failure. Reproduced with a mock multicast packet containing `[]`. Source: [discovery listener](../shell/assets/scripts/localsend.py#L131).

### R10 — Ignored incoming requests leave a permanent waiting transfer

If the user leaves the accept prompt unanswered, preparation times out and sends HTTP 403 without emitting a terminal event to the shell. QML has already inserted an active waiting item and removes it only on a terminal event or explicit rejection/cancellation. The stale activity can keep the helper running after receiving is turned off. Reproduced the missing event with a mock timeout; the UI consequence follows from its event handlers. Sources: [timeout](../shell/assets/scripts/localsend.py#L219), [waiting item](../shell/services/LocalSend.qml#L119), [helper lifetime](../shell/services/LocalSend.qml#L49).

### R11 — GUI self-update looks in the wrong place after a normal copied installation

The default installer copies only `shell/` into the Quickshell configuration directory. `IriceUpdate` assumes the parent of that directory is the repository and looks there for `tools/irice-update.py`. That parent contains neither the helper nor the checkout. The installer records the real repository elsewhere, but the GUI updater does not read that record. Code inspection; applies to the normal copied installation unless `IRICE_UPDATE_REPO` is separately supplied. Sources: [installer](../install.sh#L281), [source record](../install.sh#L318), [GUI repository inference](../shell/services/IriceUpdate.qml#L19).

### R12 — Updater rollback does not cover failures after moving untracked files aside

The updater moves conflicting untracked files out of the checkout before entering its restoration handlers. A subsequent three-way merge validation or stash failure exits without restoring them. Backups remain recoverable, but the user's original files disappear from their working locations despite the update failing. Reproduced in a disposable repository by injecting a stash error. Source: [move and later failure boundary](../tools/irice-update.py#L541).

### R13 — CLI updates discard edits made directly to managed installed files

`irice update` pulls the repository and reruns the installer. The installer deletes the installed shell directory and overwrites managed Hyprland files. It does not compare or back up subsequent edits to that installed copy. This affects users editing the installed QML/modules directly; settings stored separately and the documented `custom.lua` are different cases. Code inspection. Sources: [CLI update](../tools/irice#L25), [replacement](../install.sh#L284).

### R14 — CLI plugin rebuild ignores the recorded source location

The command reads `SRC` from the installer record and uses it for shaders and native helpers, but hardcodes `$DATA/irice/src` for the glass plugin build. A supported installation from a checkout elsewhere, such as this Projects directory, can therefore fail to rebuild the plugin or target an unrelated old checkout. Code inspection. Source: [hardcoded plugin build path](../tools/irice#L45).

### R15 — Closing the shell during the save debounce loses recent edits

Normal UI-state changes wait 300 ms before saving. The destruction handler flushes only when the separate 30-second lazy timer is running, not when an ordinary save is pending. Reproduced with the actual UiState singleton: quitting 20 ms after a note edit preserved the old value; waiting 700 ms saved the new one. This can affect notes, todos, pins, and other fields during quick restarts. Source: [save scheduling and destruction](../shell/common/UiState.qml#L72).

### R16 — Two shells can overwrite each other's unrelated state edits

Both shells write the entire state object. A shell with a pending save deliberately ignores an external change, then writes its older snapshot over it; there is no merge or serialization. Reproduced with two offscreen Quickshell instances sharing a temporary state file: one saved a new desktop note, the other saved a todo, and the final file retained the todo but restored the old note. Sources: [whole-file save](../shell/common/UiState.qml#L95), [ignored external change](../shell/common/UiState.qml#L125).

### R17 — Same-title notes saved within one minute can silently lose the second note

Note filenames contain the minute and a truncated title. A second matching name is refused by shell noclobber, but QML always posts “Note saved” and returns the path without checking the command result. It can even open the older note as though it were the new one. Reproduced the exact write command: the second save failed and the first file remained unchanged. Sources: [filename precision](../shell/services/Notes.qml#L37), [unchecked save](../shell/services/Notes.qml#L59).

### R18 — Changing the image safety filter while loading can still display old explicit results

The image browser rejects every new search while `loading`, including resets after a provider or Explicit setting change. The original request is neither cancelled nor marked obsolete, and its results are appended using current provider state. Reproduced with a mock request: turning Explicit off started no replacement request and the old result was displayed. Provider changes can also produce wrong links and parsing. Source: [search request lifecycle](../shell/modules/sidebar/Booru.qml#L42).

### R19 — Several valid calendar recurrence rules generate missing or wrong dates

Reproduced using the actual expansion function: monthly `BYDAY=MO` produces no Mondays; `BYMONTHDAY=-1` can produce February 27 instead of February 28; an annual February 29 event becomes March 1 in a non-leap year instead of skipping that year. These can cause missed or incorrectly timed entries and reminders. Source: [monthly and yearly expansion](../shell/services/Calendar.qml#L329). Expected rule/date behavior is defined in [RFC 5545 §3.3.10](https://www.rfc-editor.org/rfc/rfc5545#section-3.3.10).

### R20 — Older recurring series with COUNT disappear after the expansion guard

Fast-forwarding toward the requested date is disabled whenever COUNT exists, but iteration still stops after 2,000 intervals. A valid long-running series can therefore vanish while occurrences remain. Reproduced: a daily series beginning in 2010 with COUNT=10000 returned no occurrence for October 2026. Source: [fast-forward condition and guard](../shell/services/Calendar.qml#L317).

### R21 — Private UI state is created with group/world read permission under a common umask

The shared state file contains desktop notes, todos, and pinned clipboard text. Its writer does not enforce owner-only permissions. With umask 022, a fresh file was created as 0644 in the offscreen reproduction. Another local account can read it if the parent directories are traversable. This is conditional on directory permissions and umask; AI credential storage uses a separate path and is not implicated by this test. Source: [state writer](../shell/common/UiState.qml#L95).

### R22 — The isolated TTY shell changes the user's normal desktop theme files

AppTheme runs its helper through `Launch.wrap`, which strips the isolated XDG paths in a TTY session. The helper consequently writes the real user's KDE/Dolphin/Qt palette and desktop preference, even with optional accent matching off. That can change the appearance of the other desktop session and defeats the stated configuration isolation. Code inspection; no real palette files modified during the audit. Sources: [theme launch](../shell/services/AppTheme.qml#L33), [XDG scrubbing](../shell/common/Launch.qml#L15), [theme writes](../shell/assets/scripts/desktop-theme.py#L90).

### R23 — Right and middle clicks can activate native titlebar window actions

The native controls handler checks whether a mouse button was pressed, but never checks which button. A right or middle press over the close control therefore calls `sendClose`; other controls similarly minimize or maximize. This can unexpectedly dismiss an application or its unsaved work flow. Code inspection; live windows were not closed for testing. Source: [button handler](../hypr/plugin/irice-glass/controls.cpp#L240).

### R24 — Cancelling a stale copy activity can signal an unrelated process

The transfer watcher reports a PID without its start identity. If the copy exits and that PID is reused before the UI refreshes, Cancel sends SIGINT to the new process. This requires a narrow PID-reuse window, but the consequence can be stopping unrelated work. Code inspection. Sources: [cancel by PID](../shell/services/Transfers.qml#L52), [polling interval](../shell/assets/scripts/transfers.sh#L47).

## Low / minor

### R25 — Screenshots taken within the same second share a filename

The timestamp stops at seconds, and `grim` writes directly to that destination. Fast repeated captures can replace the earlier image instead of producing two files; older notifications then refer to the replacement. Code inspection. Sources: [timestamp](../shell/services/ScreenTools.qml#L35), [destination](../shell/services/ScreenTools.qml#L97).

### R26 — Screen translation can stay busy forever after an OCR failure

`failed("translate")` posts a notification but leaves `translation.busy` true. The result card can remain in its loading state after tesseract fails or is missing. Reproduced by invoking the actual failure function with a busy translation state. Source: [failure handling](../shell/services/ScreenTools.qml#L185).

### R27 — Clearing the translator input does not cancel the previous translation

The empty-input branch clears the result and returns before stopping the process. Its old output handler can subsequently put a translation back into an empty form. Reproduced that empty input leaves the old process marked running. Sources: [early return](../shell/modules/sidebar/Translator.qml#L35), [unconditional output assignment](../shell/modules/sidebar/Translator.qml#L47).

### R28 — An older weather response can overwrite a newly selected location

Overlapping refreshes have no cancellation or request-generation check. If the request for city A completes after the request for city B, A's data wins while the label reads current settings, potentially showing city B with A's weather until the next refresh. Code inspection. Sources: [request lifecycle](../shell/services/Weather.qml#L41), [label from current settings](../shell/services/Weather.qml#L73).

### R29 — Screen Time may not begin counting the initial active application

If the active app is recognized before UiState finishes loading, `restart()` sets `counting` to empty. There is no handler to restart counting when UiState becomes ready, and its timer only runs when counting is nonempty. Usage remains uncounted until a focus or idle change. Reproduced the initialization ordering with the actual function; live timing was not forced. Source: [initialization dependencies](../shell/services/ScreenTime.qml#L64).

### R30 — The Pomodoro countdown loses elapsed time during stalls and suspension

The countdown subtracts one per timer callback rather than deriving remaining time from a deadline. Missed callbacks during an event-loop stall or suspension do not catch up, so a running timer can finish substantially late. This is separate from an explicitly paused timer. Code inspection. Source: [countdown tick](../shell/services/Timers.qml#L90).

### R31 — Today can open after its automatic display setting is switched off

The initial check verifies that Today is enabled, then schedules a delayed opening. The delayed callback rechecks readiness and day, but not the display setting. Turning that setting off during the 0.9–2.8 second interval can still open Today. Code inspection. Source: [scheduling and delayed callback](../shell/services/Today.qml#L90).

### R32 — Today's once-per-day widget marker is not independently scheduled for saving

`todayEnsured` is included in the saved JSON but lacks a change handler that schedules a save. A marker change alone can remain only in memory until another field happens to save. Restarting in that state can restore a Today widget the user already removed, contrary to the once-per-day behavior. Code inspection; conditional on no other state save occurring. Sources: [marker update](../shell/services/Today.qml#L141), [state change handlers](../shell/common/UiState.qml#L48).

### R33 — Local events ending at a day boundary can appear in the next day's query

Local overlap testing uses `end >= from`, while the API describes a half-open range. An all-day event ending at midnight is therefore included in the following day's query as well. Subscribed events use a different test. Code inspection; the visible effect depends on which view consumes the query. Source: [local overlap test](../shell/services/Calendar.qml#L35).

### R34 — The greeter breaks session commands containing quoted arguments

Session Exec lines are split on literal spaces without desktop-entry argument parsing. A quoted path or an argument containing spaces becomes multiple incorrect arguments, potentially failing to launch the selected session after authentication. Code inspection; standard simple session commands are unaffected. Source: [session launch parsing](../shell/modules/greeter/GreeterAuth.qml#L40).

### R35 — Legal filenames containing control characters break transfer-watcher JSON

The watcher escapes backslashes and quotation marks, but not newlines, tabs, or other JSON control characters. Copying a file with one of these names can produce malformed, split JSON records, causing the shell to lose progress updates or retain stale activity. Code inspection. Source: [manual JSON construction](../shell/assets/scripts/transfers.sh#L39).

### R36 — The icon index can remain stale after icons are added inside existing directories

Cache freshness checks the theme root and `index.theme`, not nested icon directories or files. Installing/replacing an icon inside an existing directory need not modify either watched timestamp. The stale index may then be considered fresh for up to seven days. Code inspection. Source: [cache validation](../shell/assets/scripts/icon-index.py#L82).

### R37 — Renaming the computer does not update an already running LocalSend helper

The alias is sent when receiving changes or the helper starts, but changing the name alone triggers neither path. A continuously running receiver can keep advertising the previous name until receiving is toggled or the helper restarts. Code inspection. Source: [alias and helper synchronization](../shell/services/LocalSend.qml#L21).

### R38 — Native glass synchronization suppresses retries after a failed send

The native synchronizer records the body/monitor as sent before performing IPC. The sender silently drops connection/write/read failures and returns no status. If the same geometry is submitted afterward, it is skipped as unchanged, so a transient IPC failure can leave glass missing or stale until another relevant change. Code inspection; not a reproduced compositor failure. Sources: [cache before send](../shell/native/glasssync.cpp#L270), [silent IPC failure handling](../shell/native/glasssync.cpp#L90).

## Follow-up findings — 29 October 2026

### R40 — Floating/tiled policy generation can use the previous selection

**Severity:** Medium. **Evidence:** Reproduced with the actual WindowRules service in an offscreen Quickshell test; Hyprland events and command execution were mocked.

`onLayoutChanged` immediately applies a policy that reads the derived `floating` binding before it updates. Selecting Floating generated a Tiled default, and switching back generated a Floating default. Existing windows are rearranged asynchronously and can see the new selection instead, explaining their different behavior. A temporary candidate generating the rule directly from `layout` passed the isolated checks; implementation code has not been changed. See [the detailed diagnosis and limits](feature-gaps-and-power-strategy-2026-10-29.md#41-reproduced-timing-defect) and [WindowRules.qml](../shell/services/WindowRules.qml#L190).

### R41 — Changing only the default layout does not schedule startup-rule persistence

**Severity:** Medium. **Evidence:** Source inspection and isolated generated-file check.

The layout-change handler applies a live rule and rearranges windows but does not restart the generated-file sync timer. The startup file can retain an older layout until another synchronization event, allowing restart/reload to restore that older policy. The isolated test found no floating startup rule after selecting Floating; scheduling synchronization in the temporary candidate corrected it. Source: [layout handler](../shell/services/WindowRules.qml#L226).

### R42 — The window-rule hook detector misses the active TTY configuration

**Severity:** Medium. **Evidence:** Source inspection plus live path-existence checks; per-app removal consequences still need compositor testing.

## R44 — Clipboard images reload on every refresh, especially image-only view (medium)

**Reported 29 October; confirmed in source; fixed in working tree, live visual check pending.** Every preview process exit incremented a global version, every image URL included that version, and the panel set `cache: false`. Reopening history or refreshing therefore invalidated every decoded image even when files had not changed. The service also decoded only the first 48 images while exposing up to 200 history rows, leaving later image rows without previews.

**Change:** [Clipboard service](../shell/services/Clipboard.qml) now retains an unchanged history model and tracks each ready preview by stable path. The [panel](../shell/modules/clipboard/ClipboardPanel.qml) enables Qt image caching without versioned URLs. The [helper](../shell/assets/scripts/clipboard-previews.py) reuses existing files, atomically publishes successful decodes, serializes refresh work and supports all images in the retained history window. Failed/partial decodes never become ready images.

**Validation:** isolated tests prove cached previews do not decode again, failed decode output is not published, and the 49th–60th images are generated. Changed QML parses. Real image-grid rendering/scroll performance still needs a live-session check; Qt may evict cached images under memory pressure, so zero redecodes for all history sizes is not guaranteed.


## R45 — Stationary-pointer focus is not reevaluated after scene changes (medium)

**Confirmed mechanism; fixed in working tree; live session verification pending.** `input.follow_mouse=1` was already enabled, but Hyprland's pointer hit-test normally runs on movement. `focus_on_activate` alone cannot enforce stationary-pointer focus after switching workspaces. [Mouse](../shell/services/Mouse.qml) now coalesces workspace/open/close/move/floating events and invokes Hyprland's own hit-test at the current cursor position. The updated native plugin resets the cursor-motion timer before this hit-test, because Hyprland otherwise resets accumulated motion after 500 ms of idle and can still reject focus. [Lua targeting](../shell/assets/scripts/pointer-focus.lua) handles newly opened windows. User-confirmed exception: a newly opened input-capable window takes focus and moves the pointer into it if it opened elsewhere. Click-to-focus remains available; lock, open shell panels and region selection suppress automatic refocus.

Validation: Lua tests for stationary coordinates/new-window relocation/non-input windows; isolated Quickshell event test verifies workspace and open events dispatch correctly and lock suppresses refocus. This does not yet constitute a real multi-monitor focus test.

## R46 — Screenshot drag/window bounds can include an adjacent display (medium)

**Confirmed in source; fixed in working tree; physical multi-monitor verification pending.** RegionSelector accepted out-of-window drag coordinates and partially off-screen window rectangles unchanged. Those coordinates were passed to global `grim -g` capture. The selector and capture service now clip to the starting display. Integer capture geometry derives both edges together, preventing half-pixel rounding from including a pixel on the next monitor. Native selection confinement also prevents pointer escape when boundaries are enabled.

Validation: tests cover adjacent-screen drags, negative local coordinates, scaled logical dimensions, invalid rectangles and half-pixel edge rounding. Selection cancellation clears a pending delayed capture. The active machine currently exposes only one monitor.


## Additional findings fixed during implementation

### R47 — Outgoing sharing trusts changed source length and overstates partial acceptance (medium)

The sender read until EOF after declaring the original size and reported every requested path as sent even when the receiver accepted only a subset. It also left several connections unclosed. It now sends exactly the declared bytes, fails on early EOF, validates returned tokens, reports only accepted paths, bounds response bodies and closes connections. Real TLS transfer tests cover the ordinary path; changed-source and partial-acceptance branches were reviewed.

### R48 — Linked icon-theme directories can recurse indefinitely (low)

The index builder followed directory symlinks without tracking visited directory identities. A theme link cycle could keep walking the same tree. The shared walker visits each device/inode pair once; a symlink-cycle fixture terminates and nested changes invalidate the cache.

### R49 — Update backups created in the same second reuse a directory (low)

The updater used a second-resolution backup name with `exist_ok=True`, allowing a subsequent attempt to overwrite earlier backup contents. Backup names now include a nanosecond suffix; installed-copy backups also use high-resolution names.

### R50 — Download activity splits legal control-character filenames (low)

The download scanner used tab/newline-delimited records, independently of the copy watcher in R35. A filename containing those characters corrupted the displayed record. Both scanners now emit JSON. A fixture verifies that a filename containing a newline and tab survives serialization unchanged.

### R57 — Tapping Super does not arm the Overview shortcut (medium, corrected after live reproduction)

**Correction to the original diagnosis:** The updater successfully delivered `e9b24f5` to the running `/home/user/iRice` checkout, and Hyprland loaded its explicit release binding.
